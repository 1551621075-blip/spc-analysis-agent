# 本地使用与人工闭环

本工程只附带原创合成数据，不是已有生产系统的源码复刻，也不接生产数据库或设备。所有 `passed` 测量系统声明、校准证书、措施执行确认和随访记录都是合成演示事实，不能当作现场验证。

## 1. 安装和初始化

需要 Python 3.12、uv。以下命令在本项目根目录运行：

```bash
uv sync --locked
uv run spc-analysis init ./.spc-data
```

`init` 必须使用**尚不存在的目录**，已有空目录也拒绝，不覆盖旧用户或数据库。初始化导入原创数据，创建本地管理员，并仅显示一次管理员令牌；保存好令牌，不要提交、截图分享或写进运行时配置。令牌不是“用一次就失效”，数据库只保存其哈希。

初始化不会构建基线、批准基线、调用模型或执行设备操作。不要把初始化输出重定向到仓库内的非忽略文件。

## 2. 明确选择运行模式

先用不推理的 TEST 模式检查统计和操作流程：

```bash
uv run spc-analysis serve ./.spc-data --test-mode
```

浏览器打开 `http://127.0.0.1:8004`，输入初始化时显示的令牌。界面显式标记 TEST，不代表真实大模型验收。

使用真实本地模型时，先按 [runtime.md](runtime.md) 准备仓库外配置，再运行：

```bash
uv run spc-analysis serve ./.spc-data --runtime-config /absolute/path/outside-repository/runtime.json
```

或者使用自行启动的数值回环地址模型服务：

```bash
uv run spc-analysis serve ./.spc-data --model-url http://127.0.0.1:8080
```

三个选项必须恰好选一个。不能自动切云；启动模式标签也不等于推理成功。`/health` 的 `inferenceChecked: false` 明确表示健康检查未做模型调用。托管运行时在每次调查中惰性启动进程、复用该次调查的缓存，结束后回收，不启用系统常驻服务。

## 3. 基线不是自动批准的参数

1. 选择 `synthetic-phase-one`，显式构建草稿基线。
2. 审查数据适用性、25 个 n=5 子组、测量条件、控制限和完整审核哈希。
3. 有 reviewer/admin 权限的同一所有者填写审核意见，对精确 `content_hash` 批准或拒绝。
4. 只有批准后才能用它评估监控数据。拒绝/批准后的基线不能原地修改；换工况或重建基线需新建并重新审核。

演示管理员可以自提自审；本工程不声称实现双人职责分离。`content_hash` 绑定完整待审基线文档；文档内部的 `baseline_hash` 是统计语义哈希，两者用途不同。

CLI 等效操作（命令会以隐藏输入方式询问令牌）：

```bash
uv run spc-analysis build ./.spc-data synthetic-phase-one
uv run spc-analysis approve ./.spc-data BASELINE_ID CONTENT_HASH review-baseline-001 '已审查原创合成基线的数据条件和冻结控制限'
uv run spc-analysis evaluate ./.spc-data BASELINE_ID synthetic-monitor
```

用实际返回的 ID 和哈希替换占位值。不要把令牌放进参数或环境变量。

## 4. 评估与调查分开

正常数据可返回 `stable`；信号数据返回 `signals`；缺失、混批、MSA 不通过、校准过期等返回 `not_evaluable`。后两者都可以创建需要调查的风险，不会把不可评价当成正常。

- Xbar-R 的控制限来自已批准基线，不随当前样本重新拟合。
- 规格限只用于能力计算，不能替代控制限。
- 多条 Nelson 规则可以同时命中；其模式不是已经验证的根因。
- `Cpk/Cp` 使用本次监控数据的组内尺度，`Ppk/Pp` 使用本次全部有效测量的样本标准差。只有数据、稳定性、测量条件和样本量满足门槛时才输出，仍不证明正态性、独立性或现场合理子组成立。

选择风险后，显式创建调查并运行。模型只能选择过程上下文、测量上下文、相关措施历史和提交草稿四种动作。至少读取过程和测量两类证据才能提交。后端绑定引用、冻结风险和统计；模型叙述只在 `untrusted_model_draft` 中，不能修改权威结果，也不会创建已批准措施。

调查终态重跑不会重新调用模型。遇到未知调用结果时停止并等待人工对账，不自动重发。管理员只能声明该次调用“没有可恢复结果”，不能伪造模型响应；`tokens: null` 保守占用剩余额度，`tokens: 0` 是需要依据的明确人工声明，不是未知值的默认替代。

## 5. 措施必须逐步留痕

1. **提出**：人工填写措施描述和期望结果，形成不可变待审内容及哈希。
2. **审核**：reviewer/admin 对精确措施哈希明确批准或拒绝。
3. **执行确认**：人工填写实际观察时间、说明，并显式勾选确认。本工程只记录声明，不向设备下发指令。
4. **随访**：选用执行后、原风险窗口之后的新数据，重新按同一已批准基线计算。不能把原测量改 ID/时间戳当作新随访。
5. **关单**：随访必须满足完整数据、25 个 n=5 子组、无信号、测量条件有效等门槛；reviewer/admin 再对最新合格随访哈希明确关单。

不合格随访会记录原因，不能关单，可以用真正新的数据重新随访。稳定随访只说明其窗口满足本工程统计门槛，不证明措施造成改善。

附带合成随访是 2026 年历史数据。演示时，执行观察时间应填写在原风险监控窗口之后、随访窗口之前的合成历史时刻；不能填写“现在”后再拿之前的历史数据宣称执行后有效。

## 6. 数据导入与接口

`spc-analysis fixture --case baseline` 或 `--case mean_shift` 输出原创 Dataset JSON。`POST /api/datasets` 接受本工程严格 schema；当前工作台只选择已导入的数据集，没有文件上传或 JSON 粘贴入口。统计路径要求 n=5、明确时间戳、单位、批次、工况版本、量具、MSA 和校准声明。没有自动清洗、补零、排序、插值或静默修复。

API 的修改请求需要 JSON 对象、Bearer 令牌和合法同源请求；不提供任意文件路径、SQL 或 Python 执行接口。数据和对象按所有者及工厂范围隔离，角色变化后旧身份不能继续使用。默认关闭 Swagger/OpenAPI。

数据库、制品、凭据、模型和真实运行时配置不要入 Git。`.spc-data/` 只是一个明确忽略的默认演示目录；使用其他目录时优先放在仓库外。检查发布候选不等于检查整个 Git 索引，提交前仍要逐项核对所有待提交文件。
