# SPC 技术架构

## 先统计，再调查

输入原创合成过程数据 → 严格契约/测量适用性校验 → 已人工批准的冻结基线 → 确定性 Xbar-R 与 Nelson 规则 → 冻结评估 → 去重 RiskEvent → 受限本地模型调查 → 独立措施记录。

本项目不把统计引擎包装成语言模型，也不声称必须采用 ReAct 才能计算控制图。模型只能选择取证工具与提交调查草稿；统计事实早于模型存在，报告的 authoritative 区不可被模型改写。

## 统计边界

- 新工程示例默认合理子组 n=5、25 组基线，不声称这是原生产配置。
- 控制限来自冻结基线，规格限来自独立规格声明，二者含义不同。
- Xbar 的标准化尺度是子组均值标准差，不是单个测量值标准差。
- MSA、量具校准、数据完整性、采样、单位、稳定性和能力评价分别判断。
- Nelson 八规则识别非随机模式，不证明原因；同时使用多规则可能提高总体误报率，不承诺固定误报水平。
- 稳定不等于符合规格，能力值也不等于良品率或因果改善。

## 调查执行边界

模型可选 `get_process_context`、`get_measurement_context`、`get_action_history`、`submit_investigation`。只读工具不接受模型任意 SQL、Python、文件路径或生产端点。至少获得过程与测量证据才能提交，最终引用必须恰好覆盖本次已签发证据。

调查绑定当前身份、所属工厂、原评估、数据、基线和模型 fingerprint。调用前持久化 started；不明结果禁止自动重发。无效模型输出的可靠 usage 仍计入；未知用量须管理员对账，留空保守占用剩余预算，不默认为零。

每次调查累计预算：10 次模型调用、8 次工具、32,000 total tokens、300 秒合作式运行时间。人工暂停/进程重启不清零；300 秒不是操作系统硬终止，单次调用可能在结束后才被判超时。前缀缓存不减免输入 token 记账。托管模式 `ManagedLocalProvider` 在单次 run 范围内懒启动并复用，结束/异常后回收，无常驻守护或云回退；`--model-url` 模式只调用外部已启动的本机服务，不负责其启动、回收或跨调用缓存隔离。

模型决策投影按图种/规则/方向汇总全部命中的次数和首末索引，附完整分析哈希和明确说明，不把大量重叠窗口反复放入提示。权威评估和报告仍保留所有窗口、原始统计与签发证据。提示词要求谨慎表述，但代码不证明模型文字语义正确；草稿始终不可信，不能变成已确认根因。

## 措施生命周期

调查草稿不自动创建或批准措施。人员另行提出措施，审核绑定精确内容 hash；执行确认只是明确的人工观察声明，不代表系统对设备发过命令。随访由新的后续数据重新计算，并沿用原冻结基线；不得靠重命名原始数据或重算有利基线来宣布恢复。

有合格随访后仍需明确关单。该工程不证明措施因果效果、长期收益或现场安全。演示管理员可在自己的数据范围内完成全部步骤，不声称实现强制双人职责分离。

## 存储与信任

SQLite 短事务、版本/worker 租约、内容寻址制品、动作收据和审计分别承担原子状态、并发隔离、完整性、幂等和追踪。任务与措施仅原拥有者可访问，管理员没有跨拥有者读取捷径。拥有本机数据库和文件全部写权限的恶意主机管理员不在 hash 防护范围。

本工程为原创参考实现，不读取原生产源码或真实客户资料，不提供 MES/QMS/PLC 写入工具。
